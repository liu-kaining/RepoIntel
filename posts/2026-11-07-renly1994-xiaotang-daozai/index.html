解决的工程痛点

Windows 用户在办公时频繁切换微信/QQ、邮件、音乐播放器和 AI 账号查看额度，割裂在多个窗口；验证码需切换邮件客户端且容易泄露；现有桌面部件多依赖 Electron 占用资源高。

⚙

CTO 级技术审计

主程序在 src/main.rs 中构建 eframe/egui 无边框透明窗口，通过 Shell::new 启动托盘、媒体轮询、剪贴板监听及邮件/日程/额度等后台服务；窗口定位与多屏处理在 src/display_layout.rs，毛玻璃使用独立底板窗口配合宿主背景画刷 src/composition.rs。

src/composition.rs 用单独 HWND 承载 Windows Composition 合成视觉，并用 clip_to_pieces 将窗口区域裁成模糊块并集，既实现岛形模糊又不遮挡下层应用点击，属于较精致的工程处理。

src/otp.rs 的验证码提取采用加权打分而非单正则，内置中英文词表、HTML 强调、上下文硬丢弃（订单/金额/日期）等信号；src/mail_fetch.rs 按 MIME 分段只拉取 text/calendar 部分，避免下载附件，降低隐私与资源风险。

src/app.rs 与 src/pages.rs 等核心 UI 模块未包含在本次 code_bundle 中，无法确认页面交互状态管理和测试覆盖，因此工程质量评分受限。

src/kugou_cache.rs、src/soda_cache.rs、src/netease_timeline.rs 等第三方集成依赖读取本地进程内存或私有数据库，兼容性脆弱且易被客户端更新破坏；相关测试不少为 #[ignore]，只在本机按需运行，难以在 CI 验证。

可优先发布预览版收集反馈；补充 src/app.rs 等核心模块的单元测试与文档；对只读第三方访问增加版本探测和用户告警。

⚠

隐藏风险与雷点

  • 仅支持 Windows 10/11，且依赖特定客户端版本
  • 读取本机第三方进程内存/缓存可能触发反作弊或隐私担忧
  • 新仓库仅 4 个 commit，维护者集中，长期演进不确定
  • summary 过长，可能含废话
◈

生态与商业价值

作为 Rust/egui 桌面信息聚合工具，提供了无 Electron 的轻量替代方案，适合 Windows 效率工具赛道，但商业化仍依赖订阅制或增值服务，需持续维护第三方适配。
