解决的工程痛点

系统管理员在无公网 IPv4、跨网段场景远控多台 Windows/macOS/Linux 时，常用工具需逐台装客户端且视频编码延迟高，剪贴板、音频、权限和浏览器端体验割裂。

⚙

CTO 级技术审计

根工作区 Cargo.toml 将协议库 airhand-proto、链路库 airhand-link 与 server 分离；client/src-tauri 和 web 通过路径依赖共用链路，服务器不解析会话内容。控制流与会话流同走 QUIC：crates/airhand-proto/src/lib.rs 定义 13 字节 SessionHeader，server/src/broker.rs 按 conn_id + session_id 将两条双向流配对并零拷贝透传，帧层 crates/airhand-proto/src/framing.rs 用 u32 LE 长度前缀+postcard 编码并做上限限制。

重连与防猜码设计。server/src/broker.rs 的 resume_token 由控制码+密钥派生，带凭证请求失败一律 Offline 不透露控制码是否存在；server/src/codes.rs 用 SQLite 只存密钥哈希，绑定可跨重启保留。

音画/抖动有真实仿真测试。client/tests/avsync.test.ts 验证网络抖动下音画残差，client/tests/jitter.test.ts 验证缓冲断粮/快进；client/src-tauri/src/host/encoder/mod.rs 有 H264/H265/AV1 硬件到 OpenH264 回退链。

client/src-tauri/src/host/capture、pipeline 等屏幕采集与 Windows service 未在 code_bundle 中提供，本次结论不覆盖采集稳定性与多显示器 DPI 细节。

协议版本仍为 PROTOCOL_VERSION=6 且 README 声明仍在变动，未见 CI 配置，版本不兼容只能被 detect 不能自动解决。

先冻结协议并发布固定版本；补充缺失的 capture/pipeline 与 Windows 服务模块复审，再补跨网真实网络集成测试。

⚠

隐藏风险与雷点

  • 协议版本仍可能变化，客户端与服务端必须同版本构建（README 与 PROTOCOL_VERSION=6）
  • 未审阅 capture/pipeline 等路径，屏幕采集稳定性不可覆盖
  • Web 控制台不设 AIRHAND_WEB_PASSWORD 时公网端口无认证（web/src/main.rs 警告）
◈

生态与商业价值

可作为企业内网或运维团队的自托管远控方案，较传统 RDP/VNC 在弱网和浏览器接入上有差异化价值；但当前无稳定版本，不宜直接用于生产。
