解决的工程痛点

付费加速器按订阅收费，ISP 默认路由并非最低延迟，丢包会直接变成游戏 lag spike；玩家需要只让游戏流量走更快路径且不影响其他应用。

⚙

CTO 级技术审计

仓库 workspace 仅含 shortcut-core 与 shortcut-relay 两个 crate（Cargo.toml），路由打分、切换、去重与中继规则集中在 crates/shortcut-core/src/lib.rs；shortcut-relay 在 crates/shortcut-relay/src/main.rs 监听 UDP 7400，按 cookie 校验、token bucket 限速和 connected UDP 单目标转发，Relay::handle 依 wire 帧类型分发。桌面端仅审阅到 app/ui/app.js 的静态 UI，未包含 Tauri/Rust 后端，因此进程分流与 Wintun 实际调用本次不覆盖。

crates/shortcut-core/src/lib.rs 中 Switch::round 要求 8ms 且 3 轮连续领先才切换，当前路径掉线时立即 failover；Dedup::accept 使用 1024 窗口且处理序号回绕，配套测试覆盖双路径丢包去重。

crates/shortcut-relay/src/main.rs 的测试验证先取 cookie 再 open 才能建会话，并拒绝内网/DNS 等目标；Session::charge 在 core 中按 HEADER_BYTES 计费，限制 UDP 反射放大风险。

未审阅到 app/ 的 Rust 后端源码，无法确认它如何挂钩 Wintun、按进程过滤 UDP、验签 relays.toml，README 声称的 20 游戏识别与自建向导不在 bundle。

relay/cloud-init.yaml 仍 checkout 分支 1.3.9，而当前版本 1.4.1；且 relays.toml 中继电器地址落在 203.0.113/198.51.100/192.0.2 文档保留网段，可能为示例值。

补齐桌面端源码审阅与集成测试，验证真实路由与反作弊隔离；将 cloud-init 分支与版本对齐，使 relays.toml 支持可验证签名；为核心/中继发布独立 binaries 并在多平台 CI 上做 e2e 测试。

  • 单维护者且 3 天仅 1 次 commit，长期维护风险高

生态与商业价值

以零成本自建/社区中继替代付费游戏加速，适合 C 端游戏玩家；但依赖志愿者中继与 Oracle 免费层，规模化上限较低。
