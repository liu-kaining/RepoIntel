解决的工程痛点

BMW iDrive 7/8 MGU 车主无法把 CarPlay 的 Waze/Google Maps 导航显示在仪表盘或 HUD，原厂只允许中央屏；本项目通过补丁和自定义渲染服务解决。

⚙

CTO 级技术审计

仓库由三部分组成：native/cluster-render/Makefile 定义 KIT_SRC/CORE_SRC/UNIT_SRC 等源文件名单，包含 slots、governor、compositor、dcsm2_port 等模块，产出 host 测试与 target 二进制 cluster-render-idrive7/idrive8。native/waze-on-cluster/Makefile 编译 waze-on-cluster，复用 cluster-render 的 client/kit，并链接 MSDK/VA-API/IAS AVB 的 stub。apps/robertn_waze_cluster 是 HMI 应用，通过 Unix domain socket 与 patch daemon 和 render 服务通信。CI 在 .github/workflows/test.yml 中按路径变更触发对应组件测试，并双 runner 比对构建 artifacts 实现可复现性。

构建系统采用 Docker 固定 Ubuntu 18.04 gcc 7.5 / glibc 2.27 匹配 head unit ABI，native/cluster-render/docker/Dockerfile 有 pinned digest。Makefile 的 check-imports 步骤确保二进制只导入允许的符号，降低 ABI 漂移风险。

测试覆盖较全面：native/waze-on-cluster/patch/test/mutation_test.js 对 carplay_locate.js 做变异测试，要求定位器要么找到每个真实位点要么拒绝构建，并校验 SHA-256；native/cluster-render/test/generation_test.cpp 在临时根文件系统上验证 iDrive 7/8 代际判断逻辑。这些不是摆设。

核心渲染源码未在审阅范围内（src/compositor.cpp、src/video_layer.cpp 等），仅见 Makefile 列出的目标和测试，无法验证并发/内存安全、RAMses 生命周期管理等细节，工程分应被限制。

安装链路涉及对车机二进制的 patch（CarPlay 和 Android Auto），apps/robertn_waze_cluster/release.json 显示 "uninstallable": true，依赖 waze-on-cluster 0.9.1 写入补丁并重启 head unit；这种侵入性修改可能导致车机不稳定或保修失效。

建议先用 README 中的 host test/x86 test 验证，再在小范围硬件变体（HIGH/HIGHF）上实测；关注 open issues 中的具体车型兼容性，避免将 HUD 实验功能用于日常驾驶。

⚠

隐藏风险与雷点

  • HUD 地图被标记实验性，若头机重启两次会自动禁用 HUD 地图。
  • oap-sdk 属 BMW 专有，仓库不携带，需用户从车辆提取，存在版权/保修风险。
  • summary 过长，可能含废话
