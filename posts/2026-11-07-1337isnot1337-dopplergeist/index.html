解决的工程痛点

OSINT/音频取证分析员拿到未知飞机飞越录音时，常需手工切窗、画多普勒曲线、检索 ADS-B 历史轨迹并逐点比对，耗时且缺可复现证据链；该工具自动完成整段录音的移动音轨发现与候选位置排序。

⚙

CTO 级技术审计

CLI/本地服务提交音频后，src/dopplergeist/intake.py 用 ffmpeg 解码为磁盘 f32 缓存并校验源哈希；src/dopplergeist/discovery.py 的 discover_events 先做 24 kHz 高采样辅助解码，再跑高级发现，产生 harmonic_group_id 的事件；src/dopplergeist/pipeline.py 的 run 加载 ADS-B 轨迹（tracks.py），生成走廊网格，依次 CPA 筛选、打分、精细网格，最后经过 region_policy.py 限制策略并写 report。

src/dopplergeist/provenance.py 的 implementation_provenance 和 RunProvenance 对实现文件、配置和输入做 SHA-256 记录，并明确列出未锁定/未复制等局限；src/dopplergeist/contracts.py 的 validate_request/validate_result 强制 schema 与 UTC 时间窗，降低结果捏造风险。

src/dopplergeist/finite_search.py 的 RetentionLedger 用 SQLite 存每阶段记录、校验和，支持断点重放；parallel_tiles.py 将粗/细瓦片工作放在隔离 worker 进程并维护私有 ledger，parallel_retention.py 原子导入 worker stage，避免大规模网格搜索的内存与一致性失控。

src/dopplergeist/service.py 的 _check_origin 只校验 Host/Origin 白名单，但服务可绑定 0.0.0.0，README 建议容器内使用；若误暴露到非本地网段，上传音频与结果 API 仍可能被滥用。

src/dopplergeist/tests.yml 仅运行编译与少量真实几何/地形/机型测试，不运行生成合成输入的 pytest 套件；matching.py、geometry.py、automatic.py 等核心评分/求解器未包含在 code_bundle 中，本次结论不覆盖其内部数值稳定性和边界行为。

若作为取证工具对外提供，应补充独立验证集、错误率评估和对抗测试；优先补齐核心数值模块的回归测试与 fuzz/极小输入用例，并将本地服务默认限制在 loopback 或加认证。

⚠

隐藏风险与雷点

  • 依赖 ADSB.lol 公共存档与 Copernicus DEM，网络/地区受限时无法复现。
  • PolyForm NC 许可禁止商业使用；核心评分模块未审阅，数值路径有未验证风险。
  • Windows 原生仅可用 discover，完整分析需 WSL/容器，跨平台体验受限。
◈

生态与商业价值

面向 OSINT、音频取证与空难/冲突调查等垂直场景，提供本地可复现的候选定位与证据留痕能力；但非商用许可限制其进入商业化产品，更适合研究机构与个人调查者。
